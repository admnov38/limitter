# Data, connections, and privacy

[Back to the README](../README.md)

## Codex

install Codex and sign in with your subscription. Limitter discovers the CLI or the executable bundled with Codex/ChatGPT. It uses the read-only `account/rateLimits/read` and optional `account/usage/read` app-server methods. Codex handles authentication. A plan may return only a weekly window; Limitter uses each returned window’s actual duration. See the implementation in [Connections.swift](../Sources/LimitterCore/Connections.swift).

## Claude Code

local token history and account limits work with your signed-in Claude Code CLI. Limitter requests structured `/usage` through the CLI’s read-only `get_usage` control request, including the session, overall weekly, and named model allowances such as Fable. The structured usage interface is experimental; incompatible CLI versions show a connection error. The query disables tools, hooks, MCP servers, transcript behavior scanning, and session persistence; no model prompt is sent. Claude Code owns authentication.

The optional **Connect Claude limits** status-line connector supplies session/overall-weekly fallback readings when account polling is unavailable. Status-line quota fields require a Claude Code version and account exposing `rate_limits`; they do not currently include Fable’s separate cap. Each window can be independently absent. An absent or null percentage is shown as **Not reported**, never zero. Usage above 100% is preserved; only the meter is capped, and remaining allowance stops at zero. A percentage without a reset timestamp displays **Reset unavailable**. [Official status-line documentation](https://code.claude.com/docs/en/statusline).

The connector copies a small executable to `~/Library/Application Support/Limitter/limitter-bridge`, backs up Claude settings, and wraps the existing status-line command while preserving its output and options. Disconnect restores the previous status line. Only allowlisted quota values, per-window observation timestamps, a connector timestamp, and quota parsing errors are persisted; incoming workspace and transcript metadata are discarded. Startup/empty/null updates preserve existing windows without refreshing their observation times. Concurrent captures are serialized to avoid lost updates. Each window reports its own parsing errors. An existing connector is upgraded on app launch; **Repair connection** can reinstall it. A 30-second status-line interval is added when no interval is already configured, and disconnect restores the original options.

## Grok

install [Grok Build](https://docs.x.ai/build/overview) and sign in with `grok login`. Limitter discovers `~/.grok/bin/grok` or a CLI on your PATH, starts a short-lived `grok agent --no-leader stdio` process, and sends only ACP `initialize` and the read-only `_x.ai/billing` extension. Grok owns authentication; Limitter never reads `auth.json`, creates a session, or sends a model prompt. The weekly subscription pool is shared across Grok products. Only explicitly reported numeric percentages become meters; absent or null percentages remain **Not reported**, with the reported reset information retained. Unsupported CLI versions, sign-in failures, and timeouts have explicit connection states. Grok uses a weekly quota window and has an independent token timeframe. See [Grok subscription usage](https://docs.x.ai/grok/faq).

## Local token activity

Limitter reads `.codex/sessions`, `.codex/archived_sessions`, `.claude/projects`, and `.grok/sessions` on this Mac. These local totals are separate from account-wide subscription limits and exclude activity missing from local transcripts. Days use your current time zone. Total tokens include cache reads and writes. Codex cached input and reasoning output are already included in its reported input/output; they are not added twice. Modern Codex response IDs and Claude message IDs prevent duplicate streaming records and copied transcripts from inflating totals. Grok reads the canonical ACP `updates.jsonl` turn ledger, deduplicated by prompt ID. Input includes cached tokens, and output includes reasoning; neither is added twice. Response counts use the reported model-call count. Completed parent ledgers include their subagents, so those child logs are excluded from aggregate spend. Tokens are assigned to the time the turn completes; in-flight spend, Chat, Imagine, Voice, and API activity without a local Build transcript are excluded. Deleted or unavailable logs reduce the available history.

## Refresh and stale readings

Local logs are checked every 30 seconds, with unchanged files cached in memory. Response counts, session sets, model token totals, and quarter-hour token buckets for the retained history are indexed off the UI thread; the activity-grid hover view receives only precomputed day summaries. All three providers’ account stats refresh concurrently every two minutes; manual refresh bypasses that interval. Claude’s status-line fallback is checked every two seconds. A fresh account response takes precedence over status-line replays. Partial account updates retain the last valid model allowance until its reported reset, preserving its observation timestamp; empty duplicate model projections cannot erase numeric values. Failed or stale model-limit reads have explicit unavailable states; fallback session/weekly readings retain their original timestamps, with **Last known** and a `~` menu-bar prefix when old but unexpired. Expired windows await an actual provider update instead of assuming a reset to zero.

No telemetry, credential scraping, or API key is used. This is a local, ad-hoc-signed build; distribution to other Macs requires your own signing and notarization.

## Session state and API equivalent

Codex state follows local task start, completion, interruption, and error events. Grok state follows local streamed activity and completed/cancelled turns. Claude “Recently active” is inferred from messages; completion/stop events mark it idle. A running or recently active state expires after five minutes without log activity. These are observed transcript states, not a process monitor. The main card prefers a fresh active session, otherwise the most recently observed session. Session totals cover the available 84-day history.

API equivalent is a hypothetical **USD token cost**, not an invoice or subscription charge. By default, each response uses its recorded model’s standard API rates. Mixed Claude sessions preserve Opus, Fable, and other model usage separately, including Fable 5 versus 5.1 cache rates. Codex tracks model changes in the transcript; Grok uses the reported per-model turn breakdown. Streaming updates and copied records are deduplicated before pricing. The API Value tab lists tokens and cost for every recorded model; Overview and session cards use the same calculation.

Missing or unsupported model IDs remain **Not priced**. Partial estimates use `≥` and show the unpriced token count; an entirely unpriced period shows a dash. Unknown models never silently inherit Fable or another model’s rates. The one explicit exception is the retired `gpt-5.3-codex-spark`, which has no published rate and is quoted at GPT-5.6 Luna rates, labeled as such. **Single benchmark** mode is an explicit what-if calculation using editable per-provider rates. Existing benchmark choices are retained when upgrading, while the default calculation switches to recorded models.

Provider cards show **Input · total**, including uncached input, cache writes, and cache reads, with each component’s tokens and cost underneath. Claude’s raw `input_tokens` field covers only uncached input; new prompt content stored in cache is counted under cache writes instead. These three components are already included once in the overall estimate. Activity labels the corresponding separate metric **Uncached input**. See [Claude’s token breakdown](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance).

Standard short-context rates were checked September 7–8, 2026. Cache reads and writes are charged separately; Claude’s one-hour writes use their own rate where duration is reported, otherwise the five-minute rate applies. Tools, fast-mode and other tier premiums, long-context premiums, regional multipliers, and taxes are excluded. Rates update automatically: Limitter checks its cached catalog on launch and refreshes it daily. A newly observed, unpriced model in the last 30 days of local history triggers an early refresh, with a one-minute minimum between automatic requests. Missing prices or failed sources retry every 15 minutes while the app is running; successful discovery reprices existing history automatically. Refreshing the dashboard or choosing **Settings → API Pricing → Update now** also refreshes prices. Limitter downloads Anthropic’s pricing page (authoritative for Claude, including 5-minute/1-hour cache writes) and the [LiteLLM price list](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json) (OpenAI and xAI first-party entries), caches them in `~/Library/Application Support/Limitter/pricing.json`, and prefers them over the built-in rates. Previously downloaded model rates are retained when a source fails or omits an older model; built-in rates apply when no downloaded rate is available. New models stay unpriced until a source publishes a matching rate. Only these two price lists are contacted; no usage data is sent. Sources: [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), [xAI pricing](https://docs.x.ai/developers/pricing).
